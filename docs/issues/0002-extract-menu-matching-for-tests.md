# 0002 メニュー項目の照合のロジックを切り出してテストで守る

## 背景

「ミュート」と「ミュート解除」の取り違えを防ぐため、文言の正規化と、`data-testid` / 完全一致 / 部分一致の順の照合、除外語の判定を `content.js` に入れた（`docs/adr/0004`）。この部分は DOM に触らない純粋な処理だが、いまはファイル全体が即時関数（IIFE）の中にあり、テストから呼べない。取り違えは利用者から見て分かりにくい不具合になるので、自動で守れるようにしたい。

## やること

- 正規化と照合を `match.js`（`content.js` より先に読み込む）に切り出し、`globalThis.XOCMatch` のように公開する。
- `scripts/` のテスト（`npm run test:scripts`）から呼べる形にして、次の場合のテストを書く。
  - 「ミュート」と「ミュート解除」があるとき、ミュートを選ぶ
  - 日本語・英語・記号や空白の入った文言を正規化して一致させる
  - `data-testid` が一致する項目を、文言の一致より優先する
  - どの段でも当たらないときは `null` を返す
- `manifest.json` の `content_scripts` に `match.js` を足す（順序は `content.js` より前）。

## やらないこと

- 対応言語の追加（実機で文言が分かってから）。

## 検討した案

- `content.js` から関数だけを `export` する案: content script はモジュールとして読み込まれないので使えない。
- テスト用に `content.js` の末尾で `globalThis` に生やす案: 本番の読み込みにも手を入れることになり、切り出したほうが見通しがよいので見送った。
- jsdom で `content.js` ごと動かす案: X の DOM を模す必要があり、純粋な処理のテストには重いので見送った。

## 完了の条件

- [ ] 照合のロジックが `match.js` に移り、`content.js` はそれを呼ぶだけになった
- [ ] 「ミュート / ミュート解除」「data-testid 優先」「当たらないときは null」のテストを書いた
- [ ] `npm run test:scripts` が通り、ブラウザでの注入確認（ボタンが出て、押すと項目が選ばれる）も通った
- [ ] ADR を書いた: 照合のロジックを別ファイルに出して `globalThis` で公開する
- [ ] `docs/design.md` の 4 章 API を、切り出したファイルの名前に合わせて直した
